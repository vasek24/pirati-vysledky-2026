# Senate results page — design (v1), `senat.dg12.cz`

Date: 2026-10-10 · Branch `senate/results` · Maintainer: Václav Vislous (manages this fork) · Research: `docs/analysis/senate-research.md` (read first; facts marked [M]/[D]/[I] there).

## 1. Goal and scope
A live page of the Senate 2026 election (round 1 on 9–10 Oct, runoff 16–17 Oct), built for the Pirate Party. **v1 deliverable:** a page listing the **18 Pirate-backed candidates** (3 on the Pirate ticket, 15 endorsed — owner-supplied list is the source of truth) by constituency with live round-1 results (votes, share, rank, official status), a headline count of **constituencies decided**, and a Pirate-backed tally; **v1.1:** runoff display (same feed). Out of scope: projections/"estimated seats" (never shipped, see research §4), chamber composition (phase 2), photos, maps, precinct data, the municipal tracker, anything touching the Prague Worker or `mesta`.

**Separation (hard).** New Worker script `pirati-senat-zaloha` in a new directory `cloudflare-senat/`; client in `senat/`. No file under `cloudflare/`, `src/`, `public/`, `api/`, or the Prague/`mesta` wrangler config is edited. Code is **copied, not imported** across the boundary (`refresh.js` state machine, `edge.js`, `schedule.js`, the freshness helpers) so a change to Prague/`mesta` cannot alter this Worker and vice-versa. Only repo-level shared files get a minimal additive edit: `vitest.config.js` (extra `include` globs) and `package.json` (`build:senat`, `lint` globs if needed). Own DO namespace (class `SenatFeed`, script-scoped by name), **no KV** (not needed), own staging env, no router Worker, no shared secrets, no `GITHUB_TOKEN`.

## 2. Architecture
```
browser ─GET /api/senat─▶ Worker ─Cache API (per colo, ≤5 s)─▶ DO "senat" (SenatFeed, SQLite-backed)
                           ▲ cron * * * * *                        │ persisted last-good snapshot + nextRefreshAt
                           └───────────────────────────────────────┘ if due: conditional GET ─▶ volby.gov.cz/appdata/senat/20261009/odata/vysledky.xml
```
- **One feed, one DO** (`idFromName('senat')`, `locationHint: 'weur'`). Static assets (Vite build of `senat/`) are served by the Workers `ASSETS` binding; `/api/senat` is the only dynamic route; everything else 404 except assets.
- **Refresher** = the proven state machine of the Prague Worker, copied and reduced: single-flight refresh, persisted `{snapshot, meta}` in **one** `storage.put`, last-good never replaced by a bad candidate, backoff with jitter, `older`/`rejected`/quarantine outcomes, deadline 12 s, size guard, base/schema rehydrate check — **`meta.schema = SCHEMA + ':' + CODE_REV`**, where `CODE_REV` (file `src/rev.js`, generated by `scripts/gen-rev.mjs` and checked by a test) is the hash of `derive.js`, `normalize.js` and `manifest.js`; any change to derived output logic or the manifest discards the stored snapshot and validators on the next reload, so a fix is never masked by a `304` (the file may stay unchanged for days). Differences: **no merge step and no "complete" notion** (one file, no precinct fan-out); **conditional GET** (`If-None-Match` / `If-Modified-Since`; `304` ⇒ keep snapshot, advance `refreshedAt`/`nextRefreshAt`, reset `failures`/`stale`, no re-parse; ČSÚ's `Expires = Last-Modified + 60 s`). **Validator ownership:** validators (ETag/Last-Modified) live only in the **good** snapshot's `meta` and are written only when a candidate is installed; a `rejected`/`older`/failed response never stores validators, and **the next fetch after any non-`ok` outcome is unconditional** (so a stable-but-wrong file is re-downloaded and quarantine can count distinct 200 fetches). `fetchId` = a per-DO counter incremented on every HTTP 200 (as in Prague's feed), never the ETag; own validator (§4).
- **Upstream**: `CSU_BASE` (env only, never from a request; default `https://volby.gov.cz/appdata/senat/20261009`). Own User-Agent `pirati-senat-zaloha/0.1 (backup mirror; maintainer Vaclav Vislous +420777954389; manages this fork)`. The cookie header ČSÚ sets is ignored. Round 2 reuses the same URL (research §2.4) — there is **no round config**; round is derived from the data.
- **Schedule** (`nextRefreshAt`, `G = parsePragueTime(DATUM_CAS_GENEROVANI)`). Phases from the derived snapshot: `waiting` (every `OKRSKY_ZPRAC = 0` in every round) → `refreshedAt + 60 s`; `counting` (some obvod `counting`/`counted`/`runoff-counting`/`runoff-counted`, or round 1 started and not finished) → `clamp(G + 60 s, refreshedAt + 20 s, refreshedAt + 60 s)`, and a junk/skewed `G` (null, or `> refreshedAt + 120 s`) → `+20 s`; **`idle`** (every obvod is terminal (`elected`/`tie`) or a `runoff` with round-2 `Z = 0`, i.e. a count is finished and nothing is being counted — the days between the rounds) → `refreshedAt + 5 min`; `final` (every obvod `elected` or `tie`) → `+10 min`. Failure retry `20 s → 20–40 s → 20–60 s`. A `304` keeps the phase. `parsePragueTime` implements Europe/Prague DST (CEST until the last Sunday of October 01:00 UTC) — tested at 25 Oct 2026.
- **Close-of-polls gates** (so frozen/test data can never be published as real): `POLLS_CLOSE_R1 = 2026-10-10T14:00+02:00`, `POLLS_CLOSE_R2 = 2026-10-17T14:00+02:00` (env override `POLLS_CLOSE_R2` for a slip to 23–24 Oct). `normalize`/the refresher take `now`: **before `POLLS_CLOSE_R1` every candidate/vote/`Z` is forced to zero and no official flag is published** (`warnings: ["pre-close-data-suppressed"]` only if ČSÚ data was non-zero); **before `POLLS_CLOSE_R2` round-2 votes, round-2 `Z` and round-2 flags are dropped** (`"r2-data-suppressed"`) — ČSÚ reuses the same URL, so round-2 test data must not go out during the poll moratorium. The regression/`older` baseline (§4) applies only to snapshots whose `generated >= POLLS_CLOSE_R1` **and** which were refreshed after it.
- **Edge** (`edgeTtl` as in Prague): `Cache-Control: public, max-age=0, s-maxage=<ttl>`, ttl = `clamp(ceil((nextRefreshAt−now)/1000), 1, cap)`, `cap` 5 s in `waiting`/`counting`/stale, 600 s in `final`; last-resort copy under `/__lastresort/api/senat` (1200 s) served as `stale:true` when the DO errors/times out (13 s)/5xx, else `503 {"error":"unavailable"}`; `x-server-now` header on every reply. Cron `* * * * *` (production only) calls the DO like a viewer so the feed is warm without visitors.
- **Capacity**: one 28 KB file per minute upstream; viewers are served from the edge cache (≈1 refresh/min/colo). Not a throughput risk. Kill switch: the cron removal + `CSU_BASE`; rollback: `wrangler rollback`.

## 3. Snapshot contract (API body, `v: 1`)
Normalised from the XML + checked-in manifest; derived fields computed server-side by pure `derive.js`; the client only renders. Times: `generated` is ČSÚ's zone-less Prague string, `generatedMs` its UTC epoch.
```jsonc

  "generated": "2026-10-10T16:05:12", "generatedMs": 1791641112000,
  "round": 1,                       // 2 as soon as any HLASY_2KOLO or UCAST KOLO=2 exists
  "country": { "1": {okrskyCelkem, okrskyZprac, okrskyZpracProc, ucastProc, platneHlasy}, "2": {…}|absent },
```

### 3.1 Derivation rules (pure, unit-tested, no projection)
Let `r = round`, `rd` = the obvod's current round (2 if it has a round-2 `UCAST` or any `HLASY_2KOLO`, else 1), `Z/C` = `OKRSKY_ZPRAC`/`OKRSKY_CELKEM` of that round.
- **Obvod `state`** (first match): any `st2='ZVOLEN'` or `st1='ZVOLEN'` → `elected` (`decidedRound`); any `st2='NEZVOLEN_SHODA_HLASU'` → `tie`; `rd = 2` (round-2 `UCAST`/votes present) and no `st2` flag: `Z2 = C2` → `runoff-counted` ("sečteno, čeká na potvrzení ČSÚ"), `Z2 > 0` → `runoff-counting`, else `runoff`; any `st1='2.KOLO'` (round 2 not started) → `runoff`; else (no official flag) `Z=0`→`waiting`, `0<Z<C`→`counting`, `Z=C`→`counted`.
- **Candidate `status`** (first match, in this order): `st2='ZVOLEN'` or `st1='ZVOLEN'` → `elected`; `st2='NEZVOLEN_SHODA_HLASU'` → `runoffTie`; `st2='NEZVOLEN'` → `runoffLost`; `st1='NEZVOLEN'` → `notAdvancing` (all official, `official:true`); then, if `rd = 2` and the candidate has round-2 votes (a finalist) and `Z2 > 0`: provisional by round-2 rank — rank 1 → `runoffLeading`, else `runoffBehind` (`official:false`); `st1='2.KOLO'` (and `Z2 = 0` or round 2 not started) → `advancing` (`official:true`); remaining (round 1 without flags, `official:false`): `Z=0` → `waiting`, rank 1 → `leading`, rank 2 → `second`, else `behind`. Ties share a rank, so several candidates can be `leading`/`runoffLeading`. A withdrawn/ replacement finalist (flags change between fetches) is a legitimate change that passes quarantine (§4); `navig/obvody.json odvolaniKandidati` is logged only.
- `majority`: `2·votes > validVotes` of the current round (exact integers, not the truncated percentage) and `Z = C` and `!official`; displayed only with "čeká na potvrzení ČSÚ". **Never** call a candidate elected/advancing without the official flag.
- **Summary**: `decided` = obvody `elected`; `runoff` = `runoff` + `runoff-counting`; `awaitingOfficial` = `counted` + `runoff-counted`; `runoff` = `runoff` + `runoff-counting`; `counting`; `waiting`; `ties`. Pirate counts are over the manifest entries whose attribution verified (§5): one bucket per candidate `status`, Σ buckets = `total` (unit-tested).

## 4. Validation (`validate.js`, own — the Prague validator is list-based)
Outcome `{ outcome: 'ok'|'older'|'rejected', reason? }` on the **normalised candidate vs. last-good**:
- **Hard reject (always, never quarantined — garbage):** root not `VYSLEDKY` or `CHYBA` present; `generated` unparseable; zero obvody; an obvod with 0 candidates or without `UCAST`; negative numbers; `OKRSKY_ZPRAC > OKRSKY_CELKEM`.
- **Quarantinable structural changes** (rejected, but accepted after ≥ 3 distinct 200 fetches over ≥ 2 min, as Prague's `parties-fewer`): fewer obvody than good (or, with no good snapshot, a set differing from the manifest by more than the manifest's known obvody — the 2024 fixture is only a parser fixture); a lower candidate count in any obvod (withdrawal). An **unknown status value** is mapped to `null` with a `warnings` entry, not rejected.
- **Older replica** (only when the baseline applies, same condition as below): `generatedMs(candidate) < generatedMs(good)` → `older` (keep good, not stale, no backoff, retry at the 20 s floor).
- **Regression** (baseline applies only when the good snapshot has `generated >= POLLS_CLOSE_R1`, was refreshed after it, and has the same `base`; before that the first valid post-close candidate simply replaces the good one): `OKRSKY_ZPRAC` decreasing in any obvod/round; any candidate's `votes1`/`votes2` decreasing; an **official flag disappearing or changing** (`ZVOLEN`/`2.KOLO`/`NEZVOLEN`, `st2`) → `rejected`; quarantine accepts the same reason after ≥ 3 distinct fetches spanning ≥ 2 min. A `rejected` or `older` response also forces the next fetch to be unconditional (§2).
- **Soft checks → `warnings`, never reject:** Σ`votes` ≠ `PLATNE_HLASY` of the round (verified equal on 2024 final data); manifest name mismatch (§5). To be tightened after real counted data is seen (verification step).
- `snapshotHash` (replay/log only) excludes `generated`, fetch meta, `warnings` order.

## 5. Manifest and Pirate attribution
- `cloudflare-senat/src/manifest.js` is **generated and checked in** (script `cloudflare-senat/scripts/build-manifest.mjs`, input = registry `serk.json` + code lists `cpp.json`/`cns.json` from `SE2026reg20261007_json.zip` / `SE2026ciselniky20260915_json.zip`, output deterministic, with source URL + date + SHA-256 in a header comment). Entries per `(obvod, no)`: `{name, pre, post, first, last, age, job, residence, party (NSTRANA name), partyCode, member (PSTRANA name), ballotLabel (NAZEV_VS)}` for all 154 candidates, plus `PIRATE_BACKED = [{obvod, no, relation}]` from the owner's list (relation `ticket` for the three with `NSTRANA = 720`, `endorsed` for the other 15). A test asserts exactly 18 entries, exactly 3 `ticket` and that every `ticket` has `partyCode 720`.
- The Worker joins by `(obvod, no)` and **verifies the XML surname contains the manifest surname** (case-insensitive, diacritics-normalised); a mismatch drops the Pirate label for that candidate and adds `attribution-mismatch:<obvod>:<no>` to `warnings` plus an error log. The 154-candidate set is allowed to differ from the XML (withdrawn candidates): unknown XML candidates are shown without party info.
- **The ballot label is part of the truth:** for four endorsed candidates the official ballot label names a coalition that includes the Czech Pirate Party — Padevět (27: "Koalice … a České pirátské strany"), Dvořák (45: "Demokraté pro Hradecko (koalice STAN, Česká pirátská strana, TOP 09, …)"), Grulich (48: "… společně TOP 09, ODS, KDU-ČSL, STAN, Piráti, LES"), Třetina (54: "Znojemsko pohromadě: TOP 09, ODS, KDU-ČSL, STAN, Piráti"). The card shows both the nominating party and the ballot label ("Na lístku: …"), so Pirate involvement is neither hidden nor overstated. Whether those four get a distinct relation (e.g. `coalition`) is the owner's call; v1 keeps `endorsed` + the verbatim ballot label. `normalize` takes obvod names from the XML `NAZEV`, never from the manifest.
- **UI wording (Czech) is gender-neutral — a hard rule, owner request.** Never use a gendered noun, adjective or participle for a person (no "kandidát", "zvolen", "podporovaný", "postoupil", "navrhla", "člen/ka"). Use nouns and verbs that do not inflect for the person: relation labels **"Kandiduje za Piráty"** (ticket) and **"S podporou Pirátů"** (endorsed); statuses **"Mandát získán"**, **"Postup do 2. kola"**, **"Nepostupuje"**, **"Mandát nezískán"**, **"Shoda hlasů, mandát nezískal nikdo"**, **"Vede"**, **"2. místo"**, **"Mimo postupové pozice"**, **"Čeká na sčítání"**; party line **"Navrhující strana: {party}"**, **"Členství: {party}"**, **"Na lístku: {ballot label}"**; collective nouns "kandidatura/kandidatury". Registry text (`POVOLANI`, names, titles) is shown verbatim as ČSÚ publishes it. A test scans `senat/src/text.js` and the built page strings for a deny-list of gendered forms (`kandidát\b`, `zvolen\b`, `podporovan`, `postoupil`, `navrhla`, `člen/ka`, `nezvolen`). The nominating party is always shown (public ČSÚ fact; hiding it would mislead).

## 6. Client (`senat/`, Vite + React, own build to `senat/dist`)
- One page `/`: header (LIVE pill, "ČSÚ data z HH:MM:SS · před N s", "další kontrola za M:SS", skew-corrected via `x-server-now`; stale banner), round badge, **headline tiles** (rozhodnuto X z 27 · v druhém kole N · čeká na potvrzení · sčítá se), **Pirate tally** (18: zvoleno · postupuje · nepostoupilo · vede/2. místo · čeká), then **18 cards sorted by constituency number** with status chip, large votes/%, rank, counted-precinct progress, official/provisional marker, relation + nominating party; each card expands to all candidates of the constituency with bars; link "Zdroj: ČSÚ" (volby.gov.cz public app URL, plain `<a>`, no fetch). Mobile-first, colour never the only cue (chip text + icon), `prefers-reduced-motion`, UI copy Czech.
- Polling: copy of `schedule.js` (`nextPollDelay` with random per-tab offset 0–25 s, 5 s min gap, full-jitter backoff, hidden tabs don't poll, skew); last snapshot kept in `sessionStorage`; **the browser never requests volby.gov.cz** (CI step: `! grep -rE "appdata/senat|volby.gov.cz/appdata" senat/dist/assets`).
- Maintainer contact (repo requirement): `senat/public/{humans.txt,kontakt.txt,.well-known/security.txt}`, an HTML comment + tiny footer line "Záložní kopie · správce: Václav Vislous · 777 954 389 · zdroj dat ČSÚ"; wording "spravuje tuto kopii", never "author".
- No analytics, no cookies, no bug-report endpoint.

## 8. Risks
| # | Risk | Mitigation |
|---|---|---|
| 1 | 2026 XML during counting differs from what the frozen file/2024 final suggest | parser tolerant of unknown attributes; verify after 15:00; keep last-good; `warnings` |
| 2 | Official flag lags the counting | explicit `counted` state and "čeká na potvrzení" wording; nobody called elected without the flag |
| 3 | Wrong political attribution | owner list + registry cross-check (3 tickets ↔ NSTRANA 720) + surname verification + visible nominating party |
| 4 | Projection/legal | none shipped; research §4 |
| 5 | Upstream throttling | one conditional GET/min, own UA with contact, backoff, kill switch |
| 6 | Runoff slips (withdrawn finalist) / ties of ≥3 finalists | status model is rank/flag based, never "exactly two"; round derived from data |
| 7 | Deploy touching Prague | separate dir/script/DO, no edits under `cloudflare/`, staging first |
| 8 | Copy drift from Prague refresher | documented copy, own tests; the copy is deliberately frozen |
