## 1. Goals, non-goals, success criteria
**Goal:** a separate live product at `https://mesta.dg12.cz`: one page per town council (`/brno`, `/plzen`, …) and a mobile-first index grouped by region (kraj), for the **computed** town set (§4.1): whole-municipality councils with ≥ 10 000 inhabitants where the Pirates run on their own list (type a) or in a coalition/association list (type b), plus documented borderline (7 000–9 999) and owner-forced towns. Today's computation: **78 automatic + 1 borderline-included (Nové Město na Moravě, owner list) = 79 towns, 16 shards**, up to 8 more borderline towns pending reasons ⇒ **plan for ~85 (≤ 90)**. Nothing depends on the exact N (sized for N ≤ 120). The most important part: every page and card states **how the Pirates run in that town** (§6).

**Non-goals:** Senate; national/regional estimates, projections or sums (a region header shows only "Sečteno N z M měst"); precinct maps; candidate photos; Prague and its districts; statutory-city districts (městské části/obvody); any change to `praha.dg12.cz` (Worker `pirati-volby-zaloha`), `volby.dg12.cz`, `senat.dg12.cz`.

Success criteria:
- **M1 Prague untouched.** `npm run build` output and the Prague Worker bundle (`wrangler deploy --dry-run --outdir`) are byte-identical to the merge-base with `main` (`scripts/check-prague-unchanged.sh`, §3.1); no file reachable from Prague entry points is edited.
- **M2 ČSÚ protection.** No browser calls `volby.gov.cz` (CI grep of `dist-mesta/assets` for `appdata/kv2026`); ≤ 1 conditional fetch per ČSÚ file per feed per refresh window (≥ 20 s, ≈ 60 s typical); numbers §3.4.
- **M3 Correct inclusion and attribution.** Town set and arrangements are computed from ČSÚ data, reported in `docs/analysis/mesta-list-verification.md` and `docs/analysis/mesta-specifics.md`, checked by Codex (§6.2) and **reviewed by the owner before the domain is attached**; overrides win and must carry a reason.
- **M6 Mobile index.** At 375 px the first screen shows the search box and the "Největší města" block; first load fetches ≤ 3 shard requests (`top-1`, `top-2`, at most one region); no horizontal scroll at 320 px; tap targets ≥ 44 px.
- **M4 Correct numbers.** For 5 towns (§8) our page matches the ČSÚ results app for the same `generated` time.
- **M5 Robustness.** One failing town (data build or feed) never breaks another town, the index or Prague; existing last-good/validate/quarantine/edge/last-resort machinery reused unchanged.

## 3. Architecture
### 3.1 Product switch: zero-touch to Prague (decision)
- **Front end:** `vite.mesta.config.js` = `mergeConfig(base vite.config.js, …)`: `build.outDir 'dist-mesta'`, `publicDir 'public-mesta'`, plugins: (1) `swapModules` — `resolveId`: an import that resolves to `src/councils.js` (any relative spelling) is redirected to `src/mesta/councils.js` unless the importer is that file; (2) `mestaPatches` — `transform` applying exact-string patches from `src/mesta/patches.js` to `src/pages/CouncilApp.jsx`, `src/components/WelcomeGuide.jsx`, `src/components/ElectionHeader.jsx` (each anchor must match exactly once or the build throws) + `transformIndexHtml` (entry `/src/main.jsx` → `/src/mesta/main.jsx`, title "Volby 2026 · Piráti ve městech", description); (3) `copyShared` — emits `public/brand/*`, `public/humans.txt`, `public/kontakt.txt`. Rationale: build-time flags or extension points change Prague bytes; copying `CouncilApp.jsx` (540 lines) is the copy-paste to avoid; patches are few and unit-tested against the real files.
- **Worker:** new entry `cloudflare/mesta-worker.js` importing Prague's pure, unchanged modules (`edge.js`, `refresh.js`, `warmup.js#runWarmup`, `feedWiring.js#makeLog/phaseOfSnapshot`, `src/volby/feed.js`, `overview.js`) plus `cloudflare/mestaWiring.js`. ~150 lines of HTTP glue (`Feed.run`, `callFeed`, `reply`, `lastResort`, `api`) are copied from `worker.js` with a "keep in sync" header — accepted over refactoring the live Prague Worker. (esbuild cannot alias relative imports.)
- **Allowed edits outside mesta files:** `scripts/build-data.js` (opt-in `--product=mesta`), `package.json`/`cloudflare/package.json` scripts, `.gitignore`/`eslint.config.js` (`dist-mesta`), `.github/workflows/ci.yml`, `CLAUDE.md`, docs. **Forbidden:** other `src/`, `api/`, `cloudflare/*.js`, `cloudflare/wrangler.jsonc`, `index.html`, `vite.config.js`, `vercel.json`, `public/`.
- **Guard `scripts/check-prague-unchanged.sh [base]`** (default `git merge-base HEAD origin/main`): builds base (temp `git worktree`) and HEAD; diffs `sha256` lists of `dist/` and of the Prague `wrangler deploy --dry-run --outdir` output; fails if `git diff --name-only <base>` touches a forbidden path. Run in CI and before every merge/deploy.

### 3.4 Index data path (decision: region shards + featured shards, lazy polling) and load
| Option | Edge req / index viewer / min | ČSÚ GET/min for the index | New code |
|---|---|---|---|
| per-town summaries | N (≈ 85) | N | small |
| **shards ≤ 8, polled only while visible (chosen)** | **typ. 3–4, max S + 2 (18)** | **N + 12** | none: `createOverviewFeed` + overview refresher |
| one aggregate DO over shard DOs | 1 | N | DO→DO fan-in, new merge path, one failure domain |
- Each shard is a `useLiveResults` source `{ key:'kraj.<id>', url:'/api/kraj?s=<id>', version: OVERVIEW_VERSION, arrivals:false }` scheduled by `nextRefreshAt` + per-tab offset 0–25 s. **A region shard is mounted (fetched and polled) only while its section is expanded and on screen** (IntersectionObserver); collapsing or scrolling away unmounts the hook. Featured shards are always mounted.
- **Edge, 10 000 viewers:** typical (featured + 1–2 regions) ≈ 3.5 × 10 000 = 35 000 req/min ≈ 600 req/s; worst (everyone expands everything) 18 × 10 000 = 180 000 req/min ≈ 3 000 req/s, almost all Cache-API HITs; Worker invocations ≈ 8–43 M in 4 h (Paid, ≤ ≈ $13). Town viewers: 1 req/min.
- **DO:** ≤ 1 request per key per colo per edge TTL (1–5 s counting) ⇒ ≤ ~20 req/s per DO in the worst second, typically < 4.
- **ČSÚ (conditional GET, mostly 304), counting phase:** region shards N + featured 12 + warm town feeds 12 × 2 + on-demand town feeds ≤ (N − 12) × 2 ⇒ **≤ 3N + 12 ≈ 270 GET/min ≈ 4.5/s at N = 85**; ceiling at the 20 s floor everywhere ≈ 810/min. Independent of viewer count. No precinct files.

### 3.5 Partial builds and freshness
Shard keeps a failed town's last good summary (overview merge); a town without data shows "zatím bez dat". Each town row shows **its own** ČSÚ time (`parseCsuTime(generated)` HH:MM) and progress; no headline sums. Region header "Sečteno N z M měst" (towns with `counted ≥ total > 0`, counting only shown towns). Shard `stale:true` ⇒ orange line on that region only.

## 4. Data: generator, inclusion, overrides, data build
### 4.1 Inclusion rule (generator `inclusion` field)
Candidates = every `kvrzcoco` council with `TYPZASTUP 1`, `DRUHZASTUP ≠ 4`, plus the owner-list names. Per candidate: population `POCOBYV`, type a/b/c/d (§6), owner-list membership, automatic borderline reasons. Then:
- `auto`: population ≥ 10 000 and type a/b.
- `borderline-included`: 7 000–9 999 (or `population-band-differs`) and type a/b and ≥ 1 reason: `owner-list`; `okres-seat` (town name = `cnumnuts` NAZEVNUTS of its OKRES); `senate-seat-2026` (town name = a 2026 Senate constituency name); `pirates-2022` (a 2022 list with 720 in SLOZENI had ≥ 10 % or ≥ 1 seat: reason text "Piráti 2022: 11,7 %, 2 mand."); or a manual `borderlineReason` in overrides (Senate-constituency seat, home of a Pirate-backed candidate, high-profile coalition — free text, required).
- `borderline-excluded`: 7 000–9 999 type a/b without any reason ("borderline, no reason").
- `forced`: overrides `include: true` with `reason` (any population/type; c/d towns then render their c/d banner).
- `excluded`: everything else, with reason (`population <N>`, `type c`, `type d`, `override include:false: <reason>`).
Published set = `auto ∪ borderline-included ∪ forced`. Owner-list names that do not match exactly one council are reported as `unmatched`/`ambiguous` and stop the generator (exit 1).

- **R3 Patch drift** in Prague files: unit test + build throws on anchor miss.
