## HIGH

**H1 — The close-of-polls gates use fetch time (`now`), not the time ČSÚ generated the data, so a test file generated before close goes out as real.** `normalize.js:15-16`. A file generated at 13:58, while ČSÚ is still running test data, and fetched at 14:00:10 passes both gates. Its flags then appear live, including `ZVOLEN` → "Mandát získán". The suite actually locks this in: `normalize.test.js:80-89` runs the 2024 file (`generated` 2026-09-14) at `R1+1h` and asserts `st1 === 'ZVOLEN'` is published. A file generated before `pollsCloseR1` cannot hold real results. *Fix:* `const g = parsePragueTime(parsed.generated); preR1 = !(now >= pollsCloseR1 && g >= pollsCloseR1)`, and the same with `pollsCloseR2` for round 2. Add a test: 2024 file at `now = R2+1d` with `generated` set before R1 gives all zeros and a warning.

**H2 — Both gates fail open when the config is missing or invalid.** `normalize.js:15-16`. `now < undefined` and `now < NaN` are both `false`, so the gate turns off. I ran the 2024 final with `now` = 12 Oct and `pollsCloseR2` ∈ {`undefined`, `NaN`, `Date.parse('2026-10-24 14:00 garbage')`}. Each time the result was `round 2`, `rounds[2]` present and **no** `r2-data-suppressed` warning. With `pollsCloseR1: undefined` and `now` = 8 Oct, obvod 5 #5 publishes `votes1 4480`. The spec allows a `POLLS_CLOSE_R2` env override, so one typo publishes round-2 data during the moratorium. *Fix:* write the gate as `!(now >= close)` (closed unless proven open) and throw in `normalize` when `!Number.isFinite(pollsCloseR1/R2/now)`. Task 4 must also reject an unparseable `POLLS_CLOSE_R2` at startup.

## MEDIUM

**M1 — A structurally wrong file passes as plausible: duplicate obvods, a swapped obvod set, a vanished obvod.** The parser accepts duplicate obvods (`xml.js:91`; duplicate `UCAST` too, last wins at `:101`) and keeps reading after `</VYSLEDKY>` (`:78`). Validation compares counts only (`validate.js:73`) and returns OK on a cold start (`:118`). Evidence: appending obvod 3 a second time gives 28 obvody, `summary.pirates.total = 19`, and `validateCandidate(...,null)` → `ok`. Two documents concatenated give 54 obvody. One tag the regex cannot match (`NAZEV=Louny`) drops obvod 6 silently, leaving 26 obvody. Against a baseline, replacing obvod 1 with a second copy of obvod 2 → `ok`. Spec §4 also requires a check against the manifest's obvod set when there is no good snapshot; that check is missing. *Fix:* hard-reject duplicate `CISLO`, duplicate `PORADOVE_CISLO` within an obvod, duplicate `UCAST KOLO` and any tag after `</VYSLEDKY>`. In the validator, compare *sets* (every good `n` must be present) and, with no baseline, require the obvod set to equal the manifest's 27.

**M2 — An official flag can disappear without a rejection if its candidate's number disappears.** `validate.js:98` (`if (!c) continue`) relies on the count-based structural check. Good: `1:ZVOLEN, 2:NEZVOLEN`; candidate `2:NEZVOLEN, 5:(no flag)` → `ok`. The `ZVOLEN` disappears, which spec §4 says must be rejected. *Fix:* when a good candidate carrying a flag is missing, return `official-flag-changed` (quarantinable). More generally, compare the sets of numbers per obvod.

**M3 — The Σ-votes soft check is not implemented anywhere.** Spec §4 requires a `sum-mismatch:<obvod>:<round>` warning, and the verification step in §7(5) depends on it. `validate.js:5` says these checks live in normalize, but `normalize.js` has none; only a hash test (`validate.test.js:276`) mentions the string. *Fix:* after the gates, in `normalize`, compare Σ`votes{r}` with `rounds[r].platneHlasy` per round and push the warning. The 2024 final must give no warnings, as the existing test asserts.

**M4 — An `older` freeze: one snapshot with a future `generated` blocks every later file, and the page still shows as fresh.** `validate.js:121`. A candidate with `generatedMs = 9e15` → `ok` and is installed. After that every real file is `older`, which is not quarantinable and not stale, so this never recovers on its own. The spec itself expects a skewed `G` (§2, "`> refreshedAt + 120 s`"). *Fix:* add a hard reject `generated-future` when `generatedMs > ctx.now + 5 min`; `ctx.now` needs adding to ctx. Alternatively, let `older` count toward quarantine.

**M5 — `CODE_REV` leaves out `xml.js` and `time.js`.** `gen-rev.mjs:12`. Both change the output: the parser sets every value, and `parsePragueTime` sets `generatedMs`. A parser fix deployed between the rounds, when upstream answers 304 for days, would keep serving the old stored snapshot. This is the problem from review r1 H4, which CODE_REV was meant to fix. *Fix:* hash all `src/*.js` that are not tests and not `rev.js`, with a separator between files.

**M6 — Some tests pass for the wrong reason.** `pipeline.test.js:39` is titled "…and rejects the round-2 file replaced by the frozen one" but contains no rejection assertion. Its "valid vs. itself" checks are vacuous: both fixtures have `generatedMs` < `pollsCloseR1` (2026-09-14 and 2026-10-08), so `baselineApplies` is false and none of the regression code runs on real data. *Fix:* set `generatedMs`/`generated` to after R1 on the fixture snapshots, then assert self → `ok` and 2024-final → frozen → `rejected` (`counted-decreased`).
